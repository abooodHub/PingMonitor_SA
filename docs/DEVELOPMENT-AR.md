# دليل تطوير PingMonitor SA

## هيكل المشروع

| المسار | المسؤولية |
|---|---|
| `Core/` | تعريفات الخوادم والكتالوج ونماذج القياسات |
| `Services/` | طلبات Ping وعنوان WAN |
| `Persistence/` | حفظ القوائم وتفضيلات العرض والترحيل والاستعادة |
| `UI/Forms/` | النافذة الرئيسية والقوائم والتفاصيل |
| `UI/Controls/` | الأزرار والجدول وخانات الاختيار وشريط التقدم |
| `UI/` | تنسيق الحركة وفرز صفوف الجدول |
| `Properties/` و`Resources/` | بيانات التجميع والإعدادات والأعلام |
| `tests/` | اختبارات PowerShell والتقاط صور الواجهة |
| `scripts/` | البناء وتشغيل الاختبارات وتجهيز الإصدار |
| `docs/` | التوثيق وملفات موقع GitHub Pages |
| `release/` | حزم محلية مولدة؛ لا تُرفع ضمن مصدر Git |
| `artifacts/` | لقطات المقارنة والأرشيف ومجلدات التجهيز؛ لا تُرفع |

بقي الحل والمشروع في الجذر لتسهيل فتحهما في Visual Studio. ظلت أسماء الأنواع واسم مورد `PingMonitor.Form1.resources` وAssemblyVersion ثابتة بعد النقل للمحافظة على تحميل الواجهة وتوافق الإعدادات. أُخرج `AnimatedButton.cs` غير المستخدم من البناء، واحتُفظ بنسخة محلية في `artifacts/archive/`؛ الأزرار المستخدمة هي `ModernButton`.

## الأوامر

```powershell
# إعادة البناء والاختبار
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Build.ps1 -Test

# اختبارات إصدار مبني بالفعل
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Test.ps1

# إعادة البناء والاختبار وحزم التشغيل والمصدر
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Build.ps1 -Package
```

يكتشف سكربت البناء MSBuild بواسطة vswhere أو PATH، ويقبل `-MSBuildPath` عند الحاجة. تعمل الاختبارات في عمليات Windows PowerShell منفصلة بنمط STA لأن التطبيق يستخدم WinForms و.NET Framework.

## نطاق الاختبارات

| الاختبار | التحقق |
|---|---|
| `Run-LogicTests.ps1` | الكتالوج والمقاييس والحفظ |
| `Run-UiSmoke.ps1` | إنشاء الواجهة والقوائم والأعمدة والمزودين |
| `Run-RegressionTests.ps1` | استعادة النسخ الاحتياطية وفشل الحفظ وتبديل القوائم والفرز والبحث وCSV وإيقاف القياس واستئنافه |
| `Run-MotionSmoke.ps1` | الحركة وتقليلها وتوقف المؤقتات والتخلص من الاشتراكات |
| `Run-ProviderSwitchTests.ps1` | سرعة تغيير المزود أثناء طلبات معلقة ورفض النتائج القديمة |

اختبار تبديل المزود يحتاج شبكة تترك طلب ICMP الاختباري إلى `192.0.2.1` معلقًا لفترة قصيرة. إذا كانت الشبكة تجيب فورًا فقد يفشل شرط الإعداد؛ لا يُعالج ذلك بإزالة اختبار التجمّد أو تخفيف حدوده. أُضيفت اختبارات Run-ReleaseFeaturesTests للاستيراد والتصدير ومجاميع الجلسة، وRun-LayoutTests لمحاكاة التكبير على خمس نوافذ باللغتين. يشغّل الملف Full ثماني مجموعات، ويشغّل CI سبعًا مع إعلان استثناء اختبار الشبكة المعلقة.

صور الانحدار تُولّد عند تمرير `-Capture` وتُستبعد من المصدر في مجلد الاختبارات.

## إعداد الإصدار

مصدر رقم حزمة الإصدار هو AssemblyFileVersion في `Properties/AssemblyInfo.cs`. عند رفع الرقم حدّث أيضًا ApplicationVersion في `PingMonitor.csproj` وملاحظات الإصدار وREADME الخاص بالحزمة. لا تغيّر AssemblyVersion لمجرد تحديث رقم الحزمة؛ الإعدادات السابقة تعتمد على هوية التطبيق.

حزمة التشغيل تتضمن EXE وتعليمات التشغيل وملاحظات الإصدار. يُضمّن Runtime.config داخل EXE ويُجهّز داخل AppData قبل فتح الواجهة، دون ملف إعداد بجوار EXE. يتحقق Run-SingleFileTests من تهيئة DPI والإعدادات وإصلاح ملف التشغيل والتزامن. تُنشأ حزمة المصدر من قائمة مسارات محددة لتجنب إدخال مخرجات البناء واللقطات وبيانات المستخدم. تتحقق الاختبارات قبل إنشاء الحزم؛ ينشر GitHub Actions الإصدار بعد نجاح البناء وفحص الحزمة.

المجلد الحالي نسخة ملفات دون `.git`. عند الرفع لاحقًا، تُطبّق حزمة المصدر على نسخة مستنسخة من المستودع الأصلي مع مراجعة النقل والحذف، حتى يبقى سجل Git محفوظًا. لا يكفي الاعتماد على `.gitignore` عند رفع مجلد يدويًا؛ استخدم حزمة المصدر النظيفة.


فحص حزمة جاهزة (من Windows PowerShell بنمط STA):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Sta -File tests/Run-PackageSmoke.ps1 -PackagePath release/PingMonitor-SA-1.3.1.zip
```

هذا تحميل للبرنامج وموارده داخل عملية اختبار ببيانات معزولة، وليس تشغيلًا على تثبيت Windows نظيف. راجع قائمة التحقق الخارجي قبل نشر إصدار عام.
